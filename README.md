### `01` The Problem Solver, Not The Order-Taker

Most developers ship what's asked. I diagnose what's actually broken —
then decide whether to fix the symptom or rebuild the system underneath it.

```diff
+ Given: "the API is down"
+ Most devs: restart the server, hope it holds
+ What I do: trace it through every layer until I find the real fault —
+   network → DNS → process → OS security policy → GPU driver → silicon.
+   Fix the layer that's actually broken. Document it so it never repeats.
```

This is not theory. It's the default way I approach every system I touch —
web apps, infra, or a GPU-backed AI pipeline three layers deep in a driver
crash nobody else wanted to look at.

### `02` Where I Actually Operate

The market isn't rewarding "can write React" anymore — it's rewarding
people who can **architect systems where humans and AI agents both do
real work.** That's the layer I build in.

- 🧠 **AI-orchestrated engineering** — I direct AI agents to design, build, debug, and deploy real infrastructure, not just autocomplete functions
- 🖥️ **Self-hosted AI infra** — running my own GPU inference stack (ComfyUI + SDXL), exposed through hardened, tunnel-based public APIs
- 🩺 **Cross-layer diagnostics** — comfortable debugging from React state down to Windows Code Integrity policies and CUDA driver internals
- 🏗️ **Production EdTech systems** — auth, placement platforms, and data layers built to survive real users, not demos
- ⚙️ **Automation-first** — if I do something twice, the third time is a script or an agent doing it for me
- 🏆 GitHub Pull Shark
